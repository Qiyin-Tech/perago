# Review rules

- Treat the existing public documentation, model contracts, CLI behavior, security guarantees, and base behavior as independent contracts for test review.
- For each changed test, recover its responsibility before reading its assertion, then derive both an allowed-change probe and a contract-violating probe.
- Test examples and implementation shapes are investigation aids, not checklists or findings by themselves.
- JSON object order, private helper calls, internal collection order, and exact diagnostic formatting are not contracts unless existing documentation or consumers explicitly require them.
- A test-only PR may still introduce T1 false confidence or T2 change-detector behavior even when the production code and current test run are unchanged.
