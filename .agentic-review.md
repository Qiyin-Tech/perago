# Review rules

- Treat the existing public documentation, model contracts, CLI behavior, security guarantees, and base behavior as independent contracts for test review.
- Inventory every changed test case and assertion, group them by production-derived contract fingerprint, and require a unique fault witness for every retained case.
- Use a violating probe for false confidence, an allowed-change probe for overconstraint, and a deletion probe for redundancy; do not require all probes for every case.
- Test examples and implementation shapes aid responsibility recovery and probe selection; central mandatory sweeps and completion criteria still apply.
- For Review acceptance fixtures, derive findings from current base/head code and independent contracts; do not use earlier Agentic Review comments, summaries, or artifacts as evidence.
- JSON object order, private helper calls, internal collection order, and exact diagnostic formatting are not contracts unless existing documentation or consumers explicitly require them.
- A test-only PR may still introduce T1 false confidence or T2 change-detector behavior even when the production code and current test run are unchanged.
